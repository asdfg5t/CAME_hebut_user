# 未达标项诊断与延后实施方案

日期：2026-10-14。状态：**仅研究与构思，按用户要求等当前几项完成后再实施**。本文件不授权修改活动实验、不作为可运行配置、不声明已修好。

## 目标与阶段边界

目标是尽量缩小 WN18RR、Sports、Cloth 与论文结果的差距，优先解决有来源依据的协议差异。当前只读取论文、固定官方源码和历史训练产物；新增 GPU 任务为零，不安装训练环境依赖，不修改源代码、参数、原始数据、活动缓存或已有模型。保留前四 NC 的 430 个结果、FB 结果和全部历史试验。

2 个百分点是验收目标而非可保证结果。KG 比较 accuracy，LP 比较 MRR×100，另报告 LP 相对差及反向非重叠子集。当前已核验 WN 为 77.377154%（论文 81.97%）；Sports 为 28.983557（论文 37.68）；Cloth 为 22.442081（论文 28.88）。这些 test 数字只用于报告，不能用于下一候选的排序或参数选择。

## 已确认的证据

1. **论文版本一致。** 从 [PMLR 官方出版页面](https://proceedings.mlr.press/v306/he26at.html) 获取正式 PDF，仅在内存解析。正式文件与本地论文均为 19 页、8,098,390 字节，SHA256 均为 `a6987ae58cba31ac704c357e0ae1070497602196cab8cb3730990643e6d28820`。没有保存重复 PDF。出版页面及 PDF 注释未提供完整训练代码链接；本次检索未找到可确认属于该论文的完整作者训练仓库，不据此宣称仓库不存在。证据：`artifacts/audit/came_official_pdf_comparison_20261014.json`。

2. **LP 图处理存在明确差异。** 固定 MMGraph commit `0769fa670c69a6dc0756a2d7fc697b980e494775` 的 `lp/lp_dataset.py:38–41` 从 train 正边构图，`lp/main.py:247–249` 再双向化，`lp/utils.py:14–33` 去重并维护反向映射。现有 LP 编码使用原始有向 train 图。在线复核：[官方训练入口](https://github.com/mm-graph-benchmark/mm-graph-benchmark/blob/main/lp/main.py)、[官方数据与评测器](https://github.com/mm-graph-benchmark/mm-graph-benchmark/blob/main/lp/lp_dataset.py)。落地实现只按固定 ZIP/成员 SHA，不依赖变化的 main 分支。CAME 的图加载代码仍未公开，不能把基准设置直接写成作者设置。

3. **KG 文本封装存在差异。** 固定 OFA commit `9045ccdfa2d02fd55841700e7d72ef563bbc2de9` 的 `data/KG/gen_data.py:84` 为实体描述增加固定任务无关前缀；当前 WN 使用原始实体描述。实体初始顺序均来自 `entity2text.txt`。在线来源：[官方 KG 生成代码](https://github.com/LechengKong/OneForAll/blob/main/data/KG/gen_data.py)。论文明确沿用 OFA 的划分，不足以证明沿用了其提示文本；因此前缀是一个有来源但尚未确认的候选，不能随意做 prompt 搜索或添加关系标签。

4. **预训练覆盖低于全图，但不是仅训练种子节点。** 读取已保存种子池和只读 SQLite v2 PPR，得到上下文节点并集：Products 681,240/2,449,029（27.82%），Books-LP 157,092/636,502（24.68%），Cloth 48,010/125,839（38.15%）。这些是已存 top-128 邻域的并集，不是有效学习程度，也不代表作者使用了全节点。附录 E 只明确 Products 子集；Books/Cloth 的固定小池是额外容量适配，作者大小与混合比例未知。证据：`artifacts/audit/pretraining_context_coverage_review_20261014.json`。

5. **已完成预训练未见梯度爆炸或零向量记录。** 10,240 个更新中，三个数据集的日志均没有零文本/图像嵌入，也没有梯度超过 10,000。Books、Cloth、Products 的裁剪更新数分别为 20/4096、366/2048、80/4096；不是每一步都被强烈裁剪。损失首尾下降。没有证据支持把当前大差距直接归因于 NaN、零嵌入或全面失效的梯度更新；梯度裁剪仍是明示的工程适配。证据：`artifacts/audit/pretraining_gradient_review_20261014.json`。

6. **排名计算已有正向证据。** 当前完整官方 source/target/rank、MRR/Hits、150 固定负候选和反向重叠已核验。官方评测器使用严格大于与大于等于计数的平均排名；当前公式相同。官方 README/部分脚本写有 1000 负例，但本地发布数据实际为 150，必须用实际官方数组，不人为重采负例。不能把验证 MRR 与论文 test MRR 比较，也不照搬上游脚本以 test 返回值指导优化搜索的做法。

## 原因的当前判断

**Sports/Cloth 优先查图与采样上下文。** 双向化差异有直接源码证据。当前 PPR 按出边推进，而 GAT 在原有向图上按入边聚合；在非对称图上，所采上下文与实际信息流可能不同，须用只读邻域结构统计判断其程度。论文未指定 PPR 方向，不能直接把转置或双向称为纠错。冻结主编码器的有限头修复只使 Sports 提高 0.68pp；Cloth 两个头候选不如参考，说明现有头候选不足以关闭差距，尚不能排除其他头参数或证明编码器有错。

**WN 优先查文本语义与表示迁移。** 两个 LBFGS 候选的验证提升不足 0.5pp，未选用；训练求解器这条有限路线没有达到预声明门槛。保留头尾拼接、线性 CE 分类器与官方划分。先审查实体/关系映射、文本来源、截断和表示变化，再考虑上述唯一官方前缀候选。不能改成知识图谱排名、非线性头或带关系标签输入来凑 accuracy。

**预训练覆盖作为第二层假设。** Books/Cloth 的覆盖限制与跨域迁移差距可能有关，但节点并集、混合比例和最后一轮训练损失均不能证明因果。减小数据量更不必然提分。先完成廉价协议候选的验证诊断，再决定是否需要独立的新编码器试验。

## 当前任务完成后的实施顺序草案

本次按用户要求不实施。须先确认当前几项结束、其产物完成核验、GPU 空闲及无用户暂停。所有新实现先进行针对性验收、冻结配置与源码身份，再启动候选。

1. **LP 每项最多一个图候选。** Sports/Cloth 仅尝试有上游依据的 train-only 双向去重图，冻结现有编码器，沿用各自此前 validation 选定的预测头配方、seed=0、完整官方 validation 和 150 固定候选。保持原负采样配方，先统计其与反向正边的冲突；若实际需要修改负采样，应另行记录并限制变量，不把它偷并入“只改图”的试验。绝不把 valid/test 边拿来构图。

2. **WN 最多一个文本候选，须先完成映射审计。** 仅使用固定 OFA 的确切实体前缀，CLIP 模型/revision/L2/77-token 约定不变，保留原特征另存候选，不增加真实关系或标签信息。沿用原验证选定图、编码器、线性头及求解配方，不同时换图/学习率/seed。若证据不足或文本审计发现应先修的真实错误，则修正并重新声明该有限候选，不能先跑后补说明。

3. **按验证分数至少提高 0.5pp 的既定门槛选择。** 一次只变一个明确因素。改图后须重新提取对应完整 embedding，缓存身份不可共享旧图结果。未改善就保留参考，不重复 test。改善后锁定最佳权重、摘要、数据/图身份 SHA，重放 validation，再对完整官方 test 一次评分。LP 同时核验非重叠子集，检查提高是否主要来自官方反向重叠。

4. **独立核验并决定是否正式交接。** 重算预测/排名、核对 CSV/JSONL/TensorBoard、最佳轮/父 SHA/PNG，报告真实差值。达到目标后才将冻结单 seed 方案准备给用户做正式重复；未达到不能以增加重复次数当作修复，也不能持续看 test 搜候选。

5. **仅在前面诊断支持表示瓶颈时再设计新预训练分支。** 该分支不自动启动。目前不确定新的种子池大小、数据混合比例或 PPR 方向。优先以训练图结构和验证证据决定，单独记录资源、固定有限候选、保留 1024/18 专家/三项损失/作者模型。若重训，应另建完整声明的八轮配置；不能把追加两轮包装为原论文八轮。新编码器不替换五项已达标结果。
