## 🎯 改进策略

### 任务1: WN18RR改进 - 文本语义增强

**根本原因分析**:
1. 未使用OFA官方实体文本前缀（论文附录明确使用OFA）
2. 简单head-tail拼接线性分类器可能表达能力不足
3. 验证-测试gap 2.16pp说明过拟合

**改进方案**:

#### 阶段1: OFA文本前缀 (优先级最高)
**科学依据**: 
- 论文附录C明确使用OFA数据
- OFA `data/KG/gen_data.py:84` 为实体添加任务无关前缀
- 当前使用原始实体描述

**具体步骤**:
1. 提取OFA前缀格式：`"Entity: {entity_name}. Description: {description}"`
2. 重新生成40,943个实体的CLIP文本特征
3. 重新编码整个图（保持1024维FP32）
4. 使用新特征训练，其他配置不变

**验收标准**:
- seed=0 validation ≥ 80.79% (当前+0.5pp)
- 通过后一次完整test
- test达到2pp内则执行10 seeds

#### 阶段2: 正则化增强 (备选)
如果阶段1未达标:
- 增加weight decay
- 增加dropout到head
- 保持线性分类器结构

**资源预算**:
- 新CLIP特征: ~80MB
- 新编码缓存: ~160MB
- 训练时间: 每seed约3-5分钟

### 任务2: Goodreads-LP改进 - 协议对齐

**根本原因分析**:
1. 当前23.79% **高于** 论文10.42%约128%
2. 官方数据确认150负候选，不是1000
3. 可能的原因：
   - 负候选采样策略不同
   - 图构建方式差异
   - 评测协议理解偏差

**改进方案**:

#### 策略1: 硬负例采样
**科学依据**: 
- 当前使用随机负采样
- MMGraph官方使用难负例（BFS + 度数过滤）
- 更难的负例应该降低MRR

**具体步骤**:
1. 实现MMGraph的负例采样策略：
   - 从训练正边出发的2跳邻居
   - 过滤掉度数过低的节点
   - 保持150个负候选
2. 重新训练预测头
3. 使用相同负例重新评测

#### 策略2: 训练图双向化检查
**科学依据**:
- MMGraph `lp/lp_dataset.py` 先取train边，再`to_bidirected`
- 当前可能使用有向图
- 检查并对齐图构建协议

**验收标准**:
- MRR×100 应降低至12-14范围
- 反向重叠子集单独报告
- 必须使用官方150负候选

**资源预算**:
- 重新训练时间: 约30-60分钟
- 无需重新编码图

### 任务3: Products改进 - 容量优化

**根本原因分析**:
1. 速度瓶颈: 2.44节点/秒 << 30节点/秒目标
2. 内存压力: 10.8GB private memory
3. 完整推理需要: 2,449,029 / 2.44 ≈ 1,003,700秒 ≈ 279小时

**改进方案**:

#### 策略1: 分层推理优化
**科学依据**:
- 当前逐节点完整2跳GAT推理
- 可以复用中间层特征

**具体步骤**:
1. **第一层推理**: 
   - Text GAT层1 → 临时矩阵A (磁盘)
   - Vision GAT层1 → 临时矩阵B (磁盘)
   
2. **第二层推理**:
   - Text GAT层2: 读A，写fusion到B相应位置
   - Vision GAT层2: 读A（text已完成），与B融合
   
3. **关键优化**:
   - 按batch处理，复用邻居特征
   - 使用mmap减少内存占用
   - 增大batch size到64或128

**预期改进**:
- 内存: 临时峰值2×9.34GB = 18.68GB (C盘可用56.8GB)
- 速度: 复用邻居应提升3-5倍 → 7-12节点/秒
- 总时间: 降至60-100小时（可接受）

#### 策略2: CSC采样优化
**科学依据**:
- 当前int32 CSC已验证数值正确
- CPU采样+GPU计算分离

**具体步骤**:
1. 使用紧凑int32 CSC结构
2. 采样块转int64后送GPU
3. 增大batch size

**验收标准**:
- 完整2,449,029节点推理完成
- 数值与小batch一致（容差2e-5）
- 官方测试准确率接近81.84±2pp

**资源预算**:
- 临时缓存: ~20GB (C盘)
- 预计时间: 60-100小时
- 磁盘I/O密集

## ⚠️ 严格的学术规范

### 必须遵守的原则
1. **证据驱动**: 每个改进都有论文/上游代码依据
2. **单变量控制**: 一次只改一个因素
3. **validation选择**: 只用validation选模型
4. **完整保留**: 所有结果（包括失败）都保留
5. **如实报告**: 未达标不伪造、不挑seed、不缩测试集

### 验收标准
- WN: 80.0-84.0% (论文81.97±2)
- Books: 8.5-12.5% (论文10.42±2)
- Products: 79.8-83.8% (论文81.84±2)

### 失败预案
如果改进后仍未达标:
1. 保留全部实验证据
2. 如实报告差距
3. 标记为"需要作者原始代码确认"
4. 不进行test-driven的参数搜索
